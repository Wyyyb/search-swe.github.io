Introduction

Search is a core capability in AI agent applications, from retrieving evidence for research assistants to locating code for software agents and grounding enterprise assistants in internal knowledge. Yet building an effective search system—or improving an existing one—requires substantial engineering expertise: choices in query understanding, indexing, retrieval, and ranking must balance relevance with latency and resource use. As coding agents become part of everyday software development, a natural question arises: can they also engineer effective search systems?

We introduce Search-SWE, a benchmark for evaluating coding agents on implementing and optimizing executable search systems. Its design centers on explicit task contracts, reproducible environments with fixed inputs, and task-specific resource budgets. Agents inspect their environment, write and test code, and iterate; a separate verifier evaluates the resulting system on held-out queries, checking functionality, retrieval quality, efficiency, and compliance with task rules. The benchmark measures working systems and the practical quality–efficiency trade-offs made during development.

Contributing

Contribution guide ↗

We welcome new tasks and improvements to tools and documentation. For agent-assisted task authoring, use the create-searchswe-task skill.

  1. Create a taskFork the repository and work in a contribution branch. Create tasks/<task-name> with a unique name of up to five lowercase, hyphen-separated words, and record the authors.
  2. Define the contractSpecify inputs, interfaces, metrics and resource limits. Reuse the shared CPU/GPU images and add task dependencies; the launcher prepares the coding agent. Add a separate verifier and integrity audit, record services in task.toml, and pin inputs and hashes in assets.json with provenance and usage terms.
  3. Validate and refineRun package checks and verifier tests, then search-swe run <task-name>. Inspect trajectories, scores and judge health, fix issues, and revalidate affected checks. Record model feedback and the final tested revision in VALIDATION.md.
  4. Submit a PROpen a PR to main with task requirements, input provenance and validation evidence. Enable maintainer edits where available; state outstanding checks or hosting help needed.

Use one or two similar reviewed tasks as structural references and record them in VALIDATION.md. Maintainers use the task-review skill for publication and merge checks.
